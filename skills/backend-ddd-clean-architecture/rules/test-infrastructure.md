# Infrastructure tests and checklist

- Test use cases with gateway fakes and in-memory repositories, without importing factories, the environment, SDKs, the network or a real database.
- Test adapters with controlled clients to cover data translation, invalid responses and provider failures; use a controlled integration to validate the real behavior of the driver or SDK when needed.
- Test relevant factories for the selection and configuration of dependencies, without requiring the network just to build an instance.
- Cover the lifecycle, partial initialization, cleanup after failures and shutdown of resources.
- Validate controllers and their schemas only through HTTP E2E tests, as described in [test-organization.md](test-organization.md), without creating isolated controller tests.
- Check that no application contract imports technical types and that no use case instantiates concrete implementations.
- Check that the factory preserves the types the infrastructure needs without exposing them to the inner layers.
- Run the existing validations relevant to the change, and remove only the temporary artifacts generated by your own validation.
